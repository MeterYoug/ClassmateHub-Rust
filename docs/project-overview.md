# 班伴 ClassmateHub-Rust 项目总览

## 1. 产品定位

班伴是一款面向一线教师的本地桌面排座应用，目标平台为 Windows、macOS 和 Linux。教师在本机完成班级、学生、成绩、教室和排座规则管理，生成座位方案后可以手动调座，再导出座位表。Linux 发行版、桌面环境及处理器架构的具体支持范围以选定的目标和实际验证结果为准。

重构承接的是原排座项目的**业务需求和可验证行为**，不是原工程。桌面端新建数据模型、界面和命令，不沿用原 Web 工程的系统表、账号门禁、字典、接口包络或页面兼容层。不要求部署服务器，不做帐号体系、多端同步或多人协作。除用户主动选择的外部 AI 调用与主动点击的 GitHub Releases 更新检查外，核心流程不依赖网络。首版不承诺直接读取历史业务库；已有数据需要迁移时，优先评估经过预检的业务表格导入。

本仓库已实现基础资料、考试与成绩管理、智能排座、方案历史、座位表导出、整库备份恢复、可选 AI 排座及关于与在线检查更新，并完成相关 Windows 桌面验收。

## 2. 教师工作流

| 模块 | 目标能力 |
| --- | --- |
| 工作台 | 引导完成班级、学生、教室、规则、生成与导出；提示缺少的前置数据。 |
| 班级与学生 | 配置学段、年级、学期、科目；手动录入或批量导入学生；新学期复制班级时可选择复制学生、关系、规则和默认教室布局，不隐式复制历史成绩或方案。 |
| 考试与成绩 | 按班级维护考试、科目快照与当前考试；查看逐生成绩；部分科目补录后保留未更新科目并重算总分、排名和成绩等级。支持将考试等级同步到学生档案供排座使用。 |
| 教室与规则 | 配置行列、讲台方向、过道、不可用座位和同桌分组，并维护硬约束、评分权重及学生关系。离线引擎读取启用的规则和关系。 |
| 座位方案 | 规则生成、冲突提示、拖拽换座、锁定、重新生成、评分明细、确认与历史查看。历史方案按快照展示，不随当前教室、规则或学生资料改动而漂移。 |
| 导出与备份 | 方案导出为 PNG、Excel、PDF，可切换教师／学生视角；整库备份与恢复单独入口，恢复前明确提示覆盖范围。 |
| AI 配置 | 管理多个兼容 Chat Completions 的模型配置，支持供应商预设、默认模型、模型发现和保存前连接测试。每次确认字段后发送，结果经过本地规则校验。 |
| 应用锁 | 可选的本地访问保护（默认关闭），支持密码解锁、一键锁屏、空闲自动锁与一次性恢复码重置；密码与恢复码以 Argon2id 哈希存放在应用数据目录的 `app-lock.json`，独立于业务库与备份。仅防同机通过软件界面查看或修改，不对 `classmate_hub.db` 或备份文件做静态加密。 |
| 关于与更新 | 展示当前版本、运行平台、数据库与引擎版本、本地数据目录及 MIT 许可；支持用户主动点击直连 GitHub Releases 检查更新（兼容 `latest.json` 清单与 Releases API），并提供发布页与安装包下载链接兜底。 |

## 3. 技术架构

| 层级 | 设计 |
| --- | --- |
| 桌面与前端 | Tauri v2 + Vue 3 + Vite + Element Plus。Vue 负责交互、状态和预览，Tauri 负责跨平台窗口、系统文件对话框及本地命令。 |
| 本地业务 | Rust 负责校验、事务和持久化。Tauri IPC 按业务定义类型化输入、结果和错误；分页字段只在列表需要时返回。 |
| 排座与存储 | 排座引擎以业务快照为输入，可脱离 UI、SQLite 和网络运行。通过 `rusqlite` 使用内嵌 SQLite 与一致性备份。 |
| 配套库 | `serde`／`serde_json` 处理序列化，`calamine`／`rust_xlsxwriter` 处理 Excel，`reqwest`／`tokio` 处理可选 AI 请求，`argon2`／`getrandom`／`zeroize` 处理本地应用锁哈希、安全随机恢复码与内存清理。 |

计划中，`src/` 放置页面、组件和 IPC 调用适配；`src-tauri/src/` 按 `commands`、`domain`、`service`、`db`、`engine`、`excel`、`ai` 分工，`src-tauri/migrations/` 保存本项目的 SQLite 迁移，`src-tauri/capabilities/` 声明最小权限。文件读取和写入只覆盖用户所选文件及应用数据目录所需操作，不给界面通用文件系统或 SQL 执行能力。

## 4. 本地数据设计

数据库拟命名 `classmate_hub.db`，路径由 Tauri 应用数据目录解析，不写死各平台用户目录。应用标识须在正式创建用户库前确定，以免升级后找不到已有数据。

下列列出核心业务实体。基础数据、考试成绩和排座方案存放在业务库中，AI 配置和凭据保留在设备上。初始库无预置业务数据。

| 表 | 职责 |
| --- | --- |
| `seat_class` | 班级、学段、年级、学期、班级科目设置。 |
| `seat_student` | 班级学生、学号及排座所需特征，如身高、视力、纪律等级。 |
| `seat_classroom` | 教室布局、行列数、讲台方向。 |
| `seat_position` | 座位坐标、可用／不可用／过道状态、同桌分组。 |
| `seat_rule` | 规则类型、硬软约束、权重和规则参数。 |
| `seat_student_relation` | 学生间不同桌、不相邻、偏好同桌等关系。 |
| `seat_subject` | 公共科目模板，按学段和年级组织。 |
| `seat_exam` | 班级考试批次、考试日期、科目快照、当前考试标记。 |
| `seat_student_score` | 每次考试的逐生总分、排名和等级。同一考试、同一学生最多一条记录。 |
| `seat_student_score_detail` | 按考试、学生和科目保存单科成绩、缺考状态、单科排名与等级。 |
| `seat_plan` | 方案状态、草稿版本、种子、实际生成来源，以及班级、布局、学生、规则和排座所需考试排名的版本化快照。 |
| `seat_assignment` | 方案内唯一的学生与座位对应关系及锁定状态。学生和座位编号解释自该方案的快照。 |
| `seat_plan_score` | 按规则记录方案评分明细。 |

- **一致性**：同班有效学号唯一；每班至多一个当前考试；同一方案内学生和可用座位均不得重复。成绩必须与考试、学生归属一致；成绩合并与重算、方案保存与评分落库分别使用事务。为班级名单、考试成绩、方案历史等实际查询设置索引。
- **历史记录**：SQLite 版本 3 增加方案、分配和评分表，三者在同一事务写入。首次保存前复核源数据，已有方案按版本防止覆盖。版本 5 支持归档，新确认或重新启用方案时归档同班其他已确认方案。当前启用方案可显式编辑，历史比较与复制均使用原快照。
- **业务升级**：版本 5 补充学年、备注、学生等级与排序、默认教室、四向讲台、规则启用状态和按排名分级标记。迁移保留原坐标、配置、历史方案和已有考试成绩，历史考试可主动切换分级口径。
- **升级与排序**：拟用 `PRAGMA user_version` 跟踪增量迁移，失败时不推进版本，不自动建空库覆盖。启用外键；WAL、同步级别及等待时间在原型上验证。中文姓名与混合学号需要稳定排序，拼音、多音字、前导零和并列排序先定义测试样本，不把编码顺序直接当成拼音规则。
- **连接与耗时任务**：首版优先验证单连接串行访问；短事务读取快照，释放数据库访问后再做排座搜索、Excel 解析或网络请求，写回前校验输入仍然有效。

## 5. 排座、导入与导出

**本地规则排座。** 独立 Rust 引擎接收快照，以候选座位较少的学生优先搜索可行解，再用固定种子的移座和换座优化软评分。从四向讲台一侧计前排，同排相邻座位自动配对，显式分组优先。规则可指定多名学生，关系规则展开为所选学生的两两关系。成绩均衡使用学生档案中已同步的等级，选用旧考试时可保留总排名口径。调座、锁座和保存都校验硬约束，空白手动方案可逐步安排学生。旧方案继续使用其快照内的座位与规则。

**可选 AI 排座。** 模型配置使用完整 HTTPS Chat Completions 地址，本机回环测试也可使用 HTTP。「获取可用模型」读取所选接入点的模型清单，连接测试发送固定文本。排座逐次确认地址、模型和实际载荷。Rust 只发送一次性学生与座位编号、坐标、讲台方向、相邻与同桌分组，以及锁座、前排候选座位、不可同桌和不可相邻的关系。姓名、学号、分数、排名、学生特征、规则名称和自由文本留在本机。请求正文、响应正文和身份映射只在内存中保留。Windows 系统凭据按应用标识、模型配置和接入地址区分，升级时兼容原来按地址保存的凭据。其他平台的密钥在会话内保留，待实机验证。

AI 只提交临时编号的分配建议。应用校验完整性、编号、座位唯一性、锁座和硬约束，再按本地规则评分。失败时默认等待老师手动回退，可在本次发送前选择自动回退。回退使用同一快照、锁座和种子，并记录实际来源。取消会结束本次等待及后续处理。SQLite 版本 4 为方案增加来源字段，已有方案升级时标为离线排座。

**Excel 导入。** 学生与成绩接受原版业务表头，使用 `.xlsx` 预检、确认后写入。预检报告重复学号、未知学生或科目及非法分数，存在错误时整批不写入。成绩区分空白、缺考与清空，按科目合并并重算总分、排名与等级。新考试按班级顺序排名和四档分级，已有考试仍可使用得分率与竞赛排名。分数以百分之一分整数保存，支持导出并同步等级。

**座位表导出。** 三种格式从已保存方案读取同一份导出数据。Canvas 生成 PNG 与单页横向 A4 PDF：采用纯白底无背景色、深色表格线样式以适配黑白打印，排号与列号分别位于左侧与顶部表头，姓名居中显示（教师视角下方附学号与锁座标记），不附带规则评分。Rust 生成带版式的 Excel（学生版含班级、讲台、座位与姓名，教师版另含学号、锁座状态及评分工作表）。三种格式都通过原生「另存为」选择目标路径，完整写入后替换目标文件。

## 6. 备份与恢复

- 导出通过 SQLite [Online Backup API](https://sqlite.org/backup.html) 生成一致性快照，不直接拷贝正在使用的主库文件。系统凭据与日志不进入备份；备份含学生数据，导出界面提示妥善保管与传输。
- 恢复先只读识别来源和版本，再在暂存副本中做 [完整性与外键检查](https://sqlite.org/pragma.html#pragma_integrity_check)、必要的版本升级和业务一致性校验。有错误或备份版本较新时，不修改当前库。
- 应用用数据目录锁限制同一目录同时运行一个实例。用户确认覆盖后，暂停业务访问，验证恢复前快照并写入恢复进行中的标记，再通过 SQLite 备份接口写入当前库。
- 写入后重新打开验证，完成后清除标记并刷新界面。应用在下次启动发现中断标记时，或覆盖后的验证失败时，从恢复前快照回退。回退失败时保留恢复点和标记，暂停业务访问，并可在恢复页面重试。

## 7. 构建与分发目标

| 首批目标 | 格式和配置 | Rust 目标 |
| --- | --- | --- |
| Windows 11 x64 | 当前用户安装的 NSIS `.exe`，内置 WebView2 Evergreen 离线安装程序。MSI 暂缓。 | `x86_64-pc-windows-msvc` |
| Apple Silicon，macOS 15.0 起 | `.dmg`，启用 Hardened Runtime。 | `aarch64-apple-darwin` |
| Ubuntu 24.04 LTS x64 | `.deb`，包名为 `classmatehub`，依赖 WebKitGTK、GTK 3 和 OpenSSL 3。 | `x86_64-unknown-linux-gnu` |

在对应系统准备 [Tauri 构建依赖](https://v2.tauri.app/start/prerequisites/) 并运行 `npm ci`。Ubuntu 还需 `libssl-dev`。用下列命令构建未签名候选包，将 `<target>` 替换为表中的目标。输出位于 `src-tauri/target/<target>/release/bundle/`。三端命令已在对应的 GitHub Actions 运行器验证。

```text
node node_modules/@tauri-apps/cli/tauri.js build --target <target> --no-sign --ci -- --locked
```

由维护者手动运行源码仓库的 [Build release candidates](../.github/workflows/build-release.yml) 工作流。同一次运行从同一提交构建并测试 Windows 11 x64、macOS Apple Silicon 和 Ubuntu 24.04 LTS x64，成功后将三个安装包、`latest.json` 和 `SHA256SUMS.txt` 汇集到 Actions 的 `release-candidate` 制品。清单的下载地址指向 `ClassmateHub-Releases` 对应版本的 Release。最终签名文件若与构建制品不同，发布前须按实际分发文件重新计算 SHA-256。

- 源码与安装包分开托管。默认更新源使用 `MeterYoug/ClassmateHub-Releases`，只在用户主动检查时访问 GitHub。公开 Release 用于分发安装包、清单和校验文件。
- GitHub Release 标题标明版本和发布类型。正文用简表列出平台与架构、包型、实际大小和下载链接，每种包单独占一行，大小按附件字节数换算为 MiB。附件文件名带版本号、平台和架构。发布前核对 SHA-256，并简要列出实机验收状态及额外运行要求。源码仓库的 Release 使用同一套下载信息。
- 安装文件与用户数据分开。应用标识为 `com.classmatehub.desktop`，升级沿用原标识与安装范围。Windows 的用户数据目录为 `%APPDATA%\com.classmatehub.desktop`，默认卸载保留数据。WebView2 已存在的 Windows 11 24H2 x64 环境已验证隔离版安装、升级和重装。未预装 WebView2 的断网安装仍待实测。
- Windows 在检测到旧版 NSIS 安装时默认选中覆盖升级。`src-tauri/installer/installer.nsi` 基于 `tauri-bundler` 2.10.5 模板，定制升级提示与默认选项。升级 Tauri CLI 时应对照新版模板检查这些改动，模板许可随 Windows 包分发。 [上游 NSIS 模板](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.12.5/crates/tauri-bundler/src/bundle/windows/nsis/installer.nsi)
- 升级前通过「备份与恢复」导出 `.classmatehub-backup`。备份恢复中断时，应用会在启动时尝试回退到恢复前快照。发布时如引入数据库迁移，还要验证迁移失败回滚，以及旧版无法读取新结构时使用旧版和兼容备份恢复。跨设备迁移后需重新配置 AI 接入点和凭据。
- 项目采用 MIT，项目许可随安装包提供。Vite 生成随前端打包的依赖许可证清单 `dist/.vite/license.md`。分发时按实际目标核对锁定的 Rust 依赖、前端清单和随包的运行组件，附上第三方许可及所需的上游源码地址。Windows 使用 Microsoft 提供的 [WebView2 Evergreen 离线分发方式](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution#offline-deployment)。
- 发布前确认源码基线、版本、发布主体和渠道，复核最终安装包及 SHA-256。Windows 正式包使用 Authenticode 和可信时间戳，macOS 正式包使用 Developer ID 签名、Apple 公证和公证票据，独立分发的 DEB 提供签名校验文件和公钥指纹。正式签名、Apple 公证与公开发布分别确认。 [Apple 公证说明](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution/)
