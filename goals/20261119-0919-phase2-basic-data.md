# 第二阶段：基础资料

## 目标与边界

完成教师可使用的班级、学生、教室与座位布局、排座规则、学生关系和新学期复制；保持离线、跨平台设计，不接入成绩、排座算法、外部 AI 或原工程基础设施。数据库结构变更须另行确认；不得覆盖已有用户数据。

## 检查点

1. 审核现有实现及数据一致性，补齐基础资料校验、停用语义和可理解的错误。
2. 在现有数据结构允许范围内实现可视化教室网格编辑，保持布局及同桌分组可持久化；覆盖已有布局须明确提示并确认。
3. 为本阶段规则提供教师可操作的配置入口，兼容既有数据，不将规则存储误报为排座算法。
4. 验证新学期选择性复制、引用映射和失败回滚。
5. 完成自动化及桌面交互验收，更新使用说明与进度；仅在验收全部通过时标记完成。

## 验收

- 空库初始化、再次打开、未来版本和失败迁移保护；重复学号、跨班级引用、停用数据及无效输入被正确处理。
- 教室行列、讲台、过道、不可用座位和同桌分组可编辑、保存、重新读取和复制；无效范围不写入，失败时无部分保存。
- 规则和关系可新增、编辑、停用及重读；无效配置、重复及跨班关系被拦截。
- 新学期各复制组合符合选择，记录映射独立，失败不留下半成品。
- 前端构建、Rust 测试及桌面端关键交互通过。桌面验证最小化启动，使用隔离测试数据；若环境不允许后台观察，记录具体未验证范围，不声称通过。
- 阶段完成后更新 README、项目总览、ROADMAP 与本文件，交付验证结果和平台限制。

## 当前进度

- 已实现网格编辑、规则表单、复制映射、数据校验、状态筛选、未保存提醒及并发编辑保护；23 项 Rust 测试和前端构建通过，覆盖规则与关系生命周期、命令层重开读回、全部复制选项、迁移回滚及并发初始化。隔离模拟浏览器检查了部分界面流程、小窗口表格和写入后的刷新故障恢复。
- Windows 隔离桌面验收已通过，覆盖基础资料、布局、规则、关系、复制、重启读回和窗口关闭时的未保存提醒。macOS／Linux 实机验证仍待进行。
